# راهنمای تحویل و ارتقای PartnerConsole v1.0.13

## نسخه و دارایی‌ها

مبنای ارتقای مستقیم، نسخهٔ پایدار عمومی `v1.0.10` با کامیت `0f35813a5eee6c336f3e4b80257b2f1f2e200614` است. نسخهٔ `v1.0.13` ادامهٔ شماره‌گذاری نامزدهای داخلی است. [انتشار پایدار قبلی در GitHub](https://github.com/MoonlessWanderer/PartnerConsole/releases/tag/v1.0.10)

سه دارایی تحویل `partnerconsole.sh`، `partnerconsole-v1.0.13.tar.gz` و `SHA256SUMS` هستند. نصاب باید همان شناسهٔ کامیت و SHA-256 آرشیو را در خود داشته باشد که در شناسنامهٔ بسته و گزارش اعتبارسنجی آمده‌اند. متن آمادهٔ انتشار در [Release Notes](RELEASE_NOTES.md) قرار دارد.

## نصب تمیز Ubuntu 24.04

از پوشه‌ای که هر سه فایل را در خود دارد اجرا کنید.

```bash
sha256sum --check --strict SHA256SUMS
sudo bash ./partnerconsole.sh install --from-archive ./partnerconsole-v1.0.13.tar.gz
```

## ارتقای مستقیم

پیش از ارتقا، نسخهٔ پشتیبان داده و تنظیمات نصب را طبق [راهنمای پشتیبان‌گیری](../../../../README.md#backup-and-restore) تهیه کنید. سپس در همان پوشه اجرا کنید.

```bash
sha256sum --check --strict SHA256SUMS
sudo bash ./partnerconsole.sh update --from-archive ./partnerconsole-v1.0.13.tar.gz
```

پس از ارتقا، پاسخ سلامت و نسخهٔ API را بررسی کنید. برای نصب دارای دامنه، ورود روی HTTPS و دسترسی به پنل تنظیم‌شده را نیز بررسی کنید. بازیابی نسخهٔ قبلی باید کد و دادهٔ سازگار را با هم برگرداند. اجرای دستی کد قدیمی روی داده‌ای که عملیات رزروشدهٔ جدید دارد می‌تواند آن عملیات را با قواعد قدیمی تفسیر کند.

## انتشار در GitHub

پس از تأیید مالک مخزن، شناسهٔ کامیت مقصد انتشار را با شناسنامهٔ آرشیو تطبیق دهید. اگر کامیت انتشار در مرحلهٔ Merge تغییر کرد، دارایی‌ها را برای همان شناسه بازسازی و کنترل تکرارپذیری، مانیفست و آزمون نصب را روی خروجی بازسازی‌شده تکرار کنید. Release Notes و سه دارایی سازگار باید از همان کامیت ارائه شوند.
