# پوشهٔ خودکفا

ریشهٔ نصب همان پوشه‌ای است که `install.sh` در آن قرار دارد. اسکریپت‌ها این مسیر را از محل فایل خود حساب می‌کنند. `install.sh` قبل از pip و npm وارد همین پوشه می‌شود، حتی اگر از پوشه‌ای اجرا شود که کاربر برنامه حق ورود به آن را ندارد.

```text
config/          api.env و web.env، mode 600
data/            فقط اگر پایگاه داخل پوشه را انتخاب کنید
logs/            api.log و web.log
backups/         خروجی scripts/backup.sh
runtime/tmp/     TMPDIR
runtime/cache/   cache پایپ، npm، XDG و bytecode پایتون
runtime/pids/    pid فرآیندهای start.sh
backend/.venv    محیط Python همین پوشه
deploy/          lockfile و قالب‌های نصب؛ خروجی render در deploy/generated
dev/docs/       راهنماها و یادداشت انتشار جاری
```

این متغیرها قبل از pip، npm و اجرای برنامه ست می‌شوند: `TMPDIR`، `TMP`، `TEMP`، `XDG_CACHE_HOME`، `XDG_CONFIG_HOME`، `PIP_CACHE_DIR`، `NPM_CONFIG_CACHE`، `npm_config_tmp` و `PYTHONPYCACHEPREFIX`.

نصب پیش‌فرض بیرون از پوشه فایل برنامه نمی‌سازد و بستهٔ سیستم نصب نمی‌کند. `install.sh` اسکریپت‌های پوستهٔ همین پوشه را 755 می‌کند. `restart.sh` به‌جای اجرای مستقیم، `bash stop.sh` و `bash start.sh` را صدا می‌زند.

## استثناهایی که برنامه انتخابشان نکرده است

- محیط مجازی مسیر مفسر Python سیستم را در پیکربندی خودش نگه می‌دارد. این وابستگی سیستم است، نه دادهٔ برنامه. بعد از جابه‌جایی پوشه `bash install.sh` محیط را اگر به این پوشه تعلق نداشته باشد دوباره می‌سازد.
- `mysqldump`، خود MySQL، Node، Python و گواهی TLS وابستگی میزبان‌اند. فایل‌هایشان مال برنامه نیست.
- شناسه‌های تشخیص CSS داخل `node_modules` متعلق به Next.js هستند و به‌عنوان محل ذخیرهٔ Partner Console استفاده نمی‌شوند. این انتشار آن‌ها را تغییر نداده است.
- اگر فرآیندی را بیرون از این اسکریپت‌ها شروع کنید، temp و cache همان محیط خودتان را دارند.
- جملهٔ مربوط به راه‌اندازی میزبان در درخواست ناقص بود. رفتار پیاده‌شده این است که قالب systemd و nginx فقط داخل پوشه render می‌شود و به مدیر سرویس یا وب‌سرور کپی نمی‌شود.

مسیر نصب نباید فاصله یا خط جدید داشته باشد. `start.sh` و مدیر سرویس را همزمان برای یک پوشه اجرا نکنید.
