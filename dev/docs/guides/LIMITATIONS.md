# محدودیت‌های باقی‌مانده — Partner Console 1.0.4

آماده بودن این بسته، تأیید Production برای کل سیستم یا برای V2Board نیست.

## V2Board و Laravel

V2Board هدف این نسخه هنوز Laravel 8 است و برای Production Ready اعلام نمی‌شود. در کنترلر کاربر، `sort_type` فقط به ASC/DESC محدود است و خود ستون `sort` به `orderBy` می‌رود. همین الگو در مسیرهای دیگری از همان خانواده دیده شده است. این همان الگوی CVE-2026-37505 است و در این انتشار patch نشده است.

Audit قبلی Composer این موارد را ثبت کرده بود و در این نوبت دوباره اجرا یا رفع نشد: CVE-2026-128083، CVE-2026-114509، CVE-2026-102279، GHSA مربوط به signed URL، قاعدهٔ ایمیل و CRLF، CVE-2025-27515، CVE-2026-102601، CVE-2026-123792، CVE-2026-109413، CVE-2026-45304، CVE-2026-45305، CVE-2026-45133. TokenGuard در پیکربندی بوده، ولی روی route زندهٔ `auth:api` نبوده است. سند آن بررسی تاریخی است و وضعیت یک سرور فعلی را توصیف نمی‌کند.

Partner Console پاسخ فشرده، JSON نامعتبر، مصرف منفی، شناسهٔ نامطابق و بدنهٔ بزرگ‌تر از ۲ MiB را رد می‌کند. این کنترل‌ها آسیب ستون sort در خود V2Board را نمی‌بندند.

## احراز هویت Partner Console

توکن در `localStorage` با کلیدهای `pp_token`، `pp_role` و `pp_username` می‌ماند. کوکی نشست و MFA در این نسخه نیست. XSS در صفحات بررسی‌شدهٔ قبلی تأیید نشده بود؛ اگر بعداً XSS وجود داشته باشد، توکن قابل خواندن است. خروج فقط همان نشست را باطل می‌کند.

## چیزی که این انتشار ثابت نکرد

- تست MySQL 8.4 روی schema خالی و جدا در `91.107.242.80` اجرا شد: ۸۳ مورد release و ۸ مورد integration، هر دو بدون شکست. این آزمایش دادهٔ Production، مهاجرت یک پایگاه پر، یا V2Board نیست. در pytest پیش‌فرض همان ۹۱ مورد skip می‌مانند مگر URL جدا و `isolated-schema-approved` داده شود.
- تست V2Board واقعی اجرا نشد: ۳۴ مورد skip. آزمایشگاه داخل‌فرایند جای پنل واقعی را نمی‌گیرد.
- نصب Ubuntu 24.04 در دو مسیر و با کاربر غیر root اجرا شد. این انتشار عمومی، TLS، و فعال‌سازی systemd را شامل نمی‌شود.
- health فقط `{"ok": true}` برمی‌گرداند و بعد از start، قطع دیتابیس را نشان نمی‌دهد.
- تنظیم دستی موجودی هر بار یک POST جداست.

## مرز استقرار

CORS در Production فقط مبدأ دقیق HTTPS است. این مجوز دسترسی سرور نیست. API باید پشت nginx و فقط روی `127.0.0.1` بماند. `PANEL_PRIVATE_ORIGINS` wildcard و CIDR ندارد. metadata، link-local و مقصدهای خطرناک حتی با استثنا رد می‌شوند. redirect و proxy محیطی برای تماس پنل خاموش است.

`psycopg` در وابستگی‌ها هست. bootstrap فقط SQLite و MySQL را می‌پذیرد. مقصد این نسخه MySQL 8.4 است، نه Postgres و نه SQLite توسعه.
